# ADR 0002 — Вход на сервере ИИ

**Статус:** предложено · **Этап:** 4 ([ROADMAP](../ROADMAP.md)) · **Владельцы:** AidenArokij (сервер ИИ),
skyze (приложение, Supabase, PRIVACY) · **Дата:** 01.10.2026 · **Ждёт:** новой архитектуры ИИ (этап 3)

## Проблема

Сервер ИИ (`server/`) анонимный: он не знает, кто спрашивает, лимиты считает на компьютер и IP-адрес.
Поэтому любые права на ИИ — только в интерфейсе, то есть не права. Платит за ИИ Айден; расход растёт вместе
с игроками. Это вторая половина тикета 14 (обязательный вход; предупреждение вышло в 2.2.5).

## Текущая реализация

- Приложение шлёт вопрос на `AI_SERVER` (`src/ui/about.ts`) с идентификатором устройства (`provider: 'server'`
  в `src/ui/ai.ts`).
- `server/server.mjs`: GigaChat, затем платный API; дневные лимиты на компьютер и адрес, хранятся на диске.
- Аккаунты — Supabase (Discord, Telegram), сессия хранится в настройках приложения и работает без сети.
- Свой ключ (`gemini`, `custom`) идёт мимо нашего сервера.

## Предлагаемая реализация

1. Приложение с `provider: 'server'` добавляет к запросу `Authorization: Bearer <access token Supabase>`.
   Без входа — экран ИИ предлагает войти или указать свой ключ; поиск, законы, калькулятор работают как прежде.
2. Сервер проверяет подпись токена **по публичным ключам проекта Supabase (JWKS)** — без секретов на сервере —
   и срок действия. Из токена берёт id игрока.
3. Лимит — на аккаунт; IP остаётся защитой от накруток (много аккаунтов с одного адреса). Лидерам и
   заместителям лимит выше: роль сервер читает из Supabase от имени игрока (его токен + publishable key,
   правила базы разрешают читать свои роли) и кэширует на время.
4. Права — тот же список `Capability` (ADR 0001): сервер проверяет `ai.server`, а для режима отладки —
   `ai.admin_debug`.
5. На сервере флаг «пускать без входа» — на переходный период и для отката.

## Альтернативы

- **Вход обязателен для всего приложения.** Отклонено: законы и калькулятор должны работать без входа и сети.
- **Вход только для «тяжёлых» функций, простой вопрос без входа.** Отклонено: двойные лимиты и путаница для
  игрока; граница «платит наш сервер — знаем, кто спрашивает» проще.
- **Проверять токен через API Supabase на каждый запрос.** Отклонено: лишняя задержка и зависимость; подпись
  проверяется локально по JWKS.

## Плюсы

- Права на ИИ становятся настоящими; злоупотребления видны по аккаунту.
- Лимиты честные: один игрок с двух ПК — один лимит.
- Секретов на сервере ИИ не прибавляется.

## Минусы

- Игроки без входа теряют ИИ через сервер (со своим ключом — нет).
- Сервер ИИ начинает видеть id аккаунта — это новые данные о игроке.

## Миграция

- Приложение: сначала релиз, который шлёт токен, если игрок вошёл (сервер его пока не требует).
- Сервер: включает проверку с флагом «пускать без входа», затем выключает флаг — после объявления на главной.
- `PRIVACY.md` и строка README о данных — в том же PR, что начинает слать токен.

## Риски

- Старые копии без токена перестанут получать ответы после выключения флага — объявление заранее, текст
  ошибки «обновите ассистент и войдите».
- Истёкший токен в долгой сессии поверх игры — приложение обновляет его перед запросом.
- Смена ключей подписи Supabase — сервер перечитывает JWKS по `kid`.

## Rollback

Флаг на сервере «пускать без входа» — мгновенно, без релиза приложения.
