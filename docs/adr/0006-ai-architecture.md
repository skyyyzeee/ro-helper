# ADR 0006 — Новая архитектура ИИ

**Статус:** реализовано, ждёт согласования · **Этап:** 3 ([ROADMAP](../ROADMAP.md)) · **Владелец:** AidenArokij ·
**Дата:** 02.10.2026 · **PR:** #24 (влит), #25, #27–#32

## Проблема

ИИ отвечал «по памяти» там, где база сервера молчала. Он мог показать выдуманную статью или цифру как
подтверждённую, смешать закон с правилом сервера и ответить на вопрос не об игре (погода, реальный УК РФ).
Каждый режим (разбор, адвокат, задержание, документ, тренажёр) проверялся по-своему или не проверялся вовсе.
Расход ИИ был одинаковым на любой вопрос: даже «привет» стоил вызова.

## Текущая реализация (до)

- `src/protocol/pipeline.ts`: слова закона (ИИ, вызов 1) → поиск → источники `S1…S14` → разбор (ИИ, вызов 2)
  → `validateAnswer` (статьи, части, цифры) → калькулятор.
- Ответ держал свободное поле `reply`, без проверки. Тип источника (закон / устав / правило) модели не сообщался.
- Режимы адвоката, задержания, документов и тренажёра шли мимо общей проверки.

## Предлагаемая реализация (сделано)

ИИ — **закрытый слой над базой**: источник права — только найденные статьи, проверяет программа.

```
вопрос
 → классификатор без ИИ (classify.ts): приветствие, бессмыслица, не об игре, реальные законы РФ,
   номер статьи — ответ приложения, 0 вызовов ИИ
 → словарь игроков (aliases.ts): известное выражение даёт поиску нормальную форму и область — без ИИ
 → неясно → ИИ-вызов 1 даёт и тип вопроса, и поисковые слова (один вызов)
 → область (sources.ts): законы | правила сервера | оба — база сужается ДО поиска
 → поиск только по базе → источники с типом из документа: S закон, C устав, R правило, O прочее
 → ИИ-вызов 2: единые правила (coreRules), текст игрока огорожен как данные, ответ — JSON,
   где у каждого утверждения есть id источников
 → проверки без ИИ (validate.ts, check.ts): норма есть, её передали, номер, часть, тип и область совпадают,
   цифры — из собственных источников утверждения, упомянутые статьи — среди источников,
   закон и правило не в одном утверждении
 → калькулятор считает наказание
 → ответ: «По закону» / «По правилам сервера» раздельно; сбой любой проверки — «Требует проверки»
```

- **Все режимы — через одни правила и одни проверки.** Требование адвоката, шаг задержания, документ и эталон
  тренажёра стоят только на названных источниках, иначе показываются как «не нашлось».
- **Права** (`aiCapabilitiesOf`, docs/AI_ACCESS.md): профиль из организации. Проверка, Практика и служебные
  документы — у государства. *Расходится с ADR 0001 п. 4 — см. «Открытые вопросы».*
- **Экзамен** (`npm run eval`, docs/AI_EVALUATION.md): 73 ситуации с категориями и ловушками, жёсткие ворота,
  `CONFIRMED_HALLUCINATION_RATE`, базовая линия и сравнение. Те же ворота с «нарочно плохим» ИИ — в vitest
  на каждом PR (`grounding.test.ts`).
- **Отзывы, словарь, отладка** (docs/AI_FEEDBACK.md, docs/AI_DATASET.md): 👍/👎/«Исправить» хранятся на сервере
  ИИ без id игрока; админ утверждает нормальную форму — она попадает в словарь и экзамен; админу виден путь ответа.
- **Интерфейс** (по просьбе skyze — поле внизу): чат, вкладки Разбор · Проверка · Практика внутри «ИИ»,
  документ — действие под ответом, «Дела» — панель в чате (ADR 0003, этап 5).

Модули: `src/protocol/{classify,sources,prompt,context,answer,validate,check,pipeline,grade,aliases,caseDiff}.ts`,
`server/server.mjs`, `scripts/ai-eval.ts`, экраны `src/ui/AiView.tsx`, `CasesView.tsx` и режимы ИИ.

## Альтернативы

- **Строже промпт, без проверок.** Отклонено: модель всё равно иногда «вспоминает»; защищает только программа.
- **Отдельный ИИ-движок на каждый режим или роль.** Отклонено: дублирование, разные гарантии.
- **Подтверждать ответ вторым вызовом ИИ.** Отклонено: дороже и та же ненадёжность.
- **Классификатор на ИИ.** Отклонено: на большинство вопросов хватает слов; ИИ спрашиваем один раз и вместе
  с поисковыми словами.

## Плюсы

- Выдуманная статья не может получить «Подтверждено»: экзамен на GigaChat-2 — 0% (0 из 64 разборов),
  ворота 0.
- Вопросы не по базе ничего не стоят; обычный вопрос — 2 вызова; со словарём — 1.
- Точность на экзамене: 40 → 54 из 73 после синонимов, номера статьи по источнику и переспроса.
- Один конвейер — одно место для улучшений; любая правка проверяется экзаменом до и после.

## Минусы

- Модель иногда пишет номер не того источника — ответ честно уходит в «Требует проверки» (это видно игроку).
- Часть верных ответов не проходит из-за поиска: синонимы и словарь нужно пополнять (отзывы помогают).
- Больше кода в `src/protocol`; держится тестами (ворота, экзамен).

## Миграция

- Старые сохранённые разговоры читаются (`readAnswer` понимает прежний формат с `reply`) и перепроверяются
  по текущей базе при открытии; как дела — с неизвестной базой (ADR 0003).
- Сервер ИИ: новые адреса (`/v1/feedback`, `/v1/aliases`, `/v1/examples`, `/v1/feedback/review`) — после слияния
  в main повторный `install.sh`; ключ админа — `set-key.sh admin`. Старые копии приложения работают как прежде.

## Риски

- Регрессия точности при правке промпта или синонимов. Защита — экзамен с базовой линией и `--approved`.
- Расхождение прав в приложении и на сервере. Защита — этап 4 (ADR 0002) с общим списком `Capability`.
- Словарь игроков разрастается сомнительными выражениями. Защита — только утверждённое админом.

## Rollback

Каждая часть — свой PR в `dev`; откат PR возвращает прежнее поведение, данных игроков не меняет. Сервер ИИ
работает и со старыми копиями приложения.

## Открытые вопросы (к skyze)

1. **Права по организации.** ADR 0001 п. 4: «организация ничего не закрывает». В #25/#28 Проверка, Практика и
   служебные документы закрыты для негосударственных — решение AidenArokij. Варианты: оставить (и поправить
   ADR 0001), или вернуть «показывать первым» и закрывать после подтверждения членства (ADR 0008).
2. **Названия прав.** Свести `ai.check`, `ai.practice`, `ai.debug`… со списком ADR 0001 (`ai.server`,
   `ai.own-key`, `ai.admin_debug`) — одним PR после решения п. 1.
3. **Словарь.** Утверждённые выражения (#31, сервер ИИ) должны попадать в словарь пакета (этап 2Б, ADR 0004),
   а не жить вторым словарём: предложение — `data/<server>/synonyms.json` получает их импортом, `/v1/aliases`
   остаётся для того, что ещё не попало в пакет.
4. **Кэш проверенных ответов** — ADR 0007, следующий.
