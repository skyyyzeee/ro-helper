# Фактически переданный фрагмент источника — 24 ноября 2026

Этап: устранить различие между текстом статьи у модели и текстом для числовой проверки. Это первый этап EvidenceBundle, не полная семантическая верификация.

## Что изменено

Новый разбор analyse прикрепляет к каждому Source необязательное evidence={text,complete}. text — тот же ограниченный фрагмент1800символов, который помещается в контекст. Ссылка по-прежнему указывает на полную статью: её можно открыть и дочитать. Полный текст базы не изменяется. Лимит и количество источников не увеличены; добавляется короткое пояснение для неполного фрагмента.

context.ts выводит именно сохранённый excerpt. При обрезке явно сообщает модели: окончание не включено, его условия и исключения не проверены. validate.ts и общий strayFigures используют тот же excerpt для чисел. Числа и звёзды из невидимого окончания не оправдывают утверждение модели. Источник, переданный не полностью и использованный в norms/violation/punishment/verdict/procedure/guide, делает needsReview=true и исключает status=confirmed. Неполная, но не процитированная статья сама по себе не портит ответ по полным источникам.

Независимый gate grade.ts также замечает forced-confirmed с неполным процитированным источником. Он не решает проблему смысловых ошибок в качественном утверждении с полной статьёй: прежний синтетический контрпример про разрешённую кражу остаётся актуальным.

## История

storeMessage/restoreMessage сохраняют evidence вместе с указателями на статьи. При повторном открытии неполная норма не превращается в полную только из-за доступа к полной базе. Если сохранённый excerpt больше не совпадает с текущим текстом, вывод требует проверки по текущей базе. Старые записи без evidence продолжают читаться с прежней валидацией: точный исторический контекст из отсутствующих данных восстановить невозможно. Формат StoredConversation v2 не меняется; поле необязательное. Числа в старых записях без snapshot evidence сохраняют прежнюю семантику проверки.

Снимок содержит публичный текст нормы, а не новые сведения о пользователе; получатель данных не изменён. Хранение одного разбора немного увеличивается за счёт фрагментов.

## Проверки

Новые тесты: общий текст в контексте/валидации; полная статья остаётся доступной; число987654 в невидимом окончании не проходит; неполный источник не бывает confirmed; независимый gate ловит принудительный confirmed; неполная неприменённая статья не снижает статус полного ответа; прежняя запись без метаданных читается; история сохраняет evidence и неполноту при повторном открытии.

Живой регрессионный набор `npm run eval -- --cases 1,2,98 --no-cache`:3/3, нужные УК87/УК90/КоАП9.26+rules-gov-1.20 применены; ошибок связи/формата0. p505.44с,p956.00с — три наблюдения, не SLA. Этот короткий набор проверяет регрессию, а не достаточность длинных статей. Неполнота/невидимые числа проверены детерминированными тестами; отдельный широкий live holdout ещё нужен.

## Что остаётся

1. Вместо механического начала статьи выбирать точные релевантные части с сохранением необходимых определений/исключений и общим бюджетом; если доказательств не хватает — уточнять либо расширять контекст контролируемо. Пока этот этап только честно отмечает неполноту.
2. Семантическая применимость: наличие полной статьи, цитаты и чисел не доказывает вывод. Не заявлять гарантированную правильность качественного текста.
3. Остальные режимы (документы/экзамен/проверки сотрудника), которые строят источники вне analyse, пока не получают evidence автоматически. Их прежние ограничения не скрывать.
4. Части нормы, отмена старого факта в follow-up, отрицания, исключения и новая holdout-выборка.
5. Нативная ручная проверка нового случая с длинной статьёй и истории ещё не проводилась; UI визуально не перерабатывался, проверена интеграция истории тестами.

Сервер повторно обновлять не требуется: исправление клиентское. Последний exe и итоговые полные проверки — в HANDOFF_WORKSPACE.md.
