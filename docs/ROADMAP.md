# Roadmap Кремлёвского Ассистента

Как развить ассистент из набора функций в единую платформу: снаружи — один простой инструмент поверх игры,
внутри — слои, каждый со своей задачей. Аудит текущего кода — [`ROADMAP_ARCHITECTURE.md`](ROADMAP_ARCHITECTURE.md).
Решения, которые трудно откатить, — в [`adr/`](adr/).

Этот документ — план, а не задание «сделать всё». Каждый этап берётся отдельной задачей, каждая задача —
отдельным тикетом в `.scratch/` и отдельным PR в `dev`.

## Принципы (согласованы 01.10.2026)

1. **Каждый релиз — одна функция для игроков и один шаг по архитектуре.** Фундамент не строится ради
   фундамента: шаг по архитектуре берётся тот, что открывает ближайшие функции.
2. **Макет C остаётся.** Новые возможности встраиваются в его разделы: вкладки внутри «ИИ», «Дела» из
   «Истории», команды — в быстром поиске Alt+S (это и есть Ctrl+K в рамках C), а не третий поиск.
3. **Поиск, законы, калькулятор и быстрый поиск работают без входа и без интернета.** Вход нужен только для
   ИИ через наш сервер; со своим ключом (Gemini или свой сервер ИИ) — без входа.
4. **ИИ никогда не источник права.** Он получает только найденные статьи и толкует их; проверяет
   детерминированная логика (`validate.ts`, калькулятор).
5. **Развивать существующее, а не заводить второе**: один `ServerPack`, один `CaseState`, одна система ролей
   (Supabase + RLS), одна очередь уведомлений поверх игры.
6. **Права проверяет не интерфейс.** Интерфейс прячет и показывает; разрешает или запрещает сервер (правила
   базы, сервер ИИ).

### Этап 1 — профиль организации, версия пакета, «не найдено» · skyze — **сделан**

**Релиз:** 1А и 1В — Release 2.10.0 (01.10.2026); 1Б — в `dev`, выйдет со следующим релизом. Тикеты 28–30 в
`.scratch/ro-helper-v2/issues/`.

#### 1А. Профиль организации и права (P0) — [ADR 0001](adr/0001-organization-profile-and-capabilities.md)

- **Зачем.** Одна модель «кто что может», на которую опираются показ функций, практика по организациям,
  проверка на сервере ИИ и позже разграничение. Новая организация добавляется данными, не кодом.
- **Что меняется.** `Organization` в пакете получает поля профиля; появляется чистая функция
  `capabilitiesOf(...)`, собирающая права из входа, ролей, админа и своего ключа; интерфейс показывает функции
  по правам, а не по отдельным условиям.
- **Модули.** `src/core/model.ts`, `src/importer` (профили из `data/<server>/`), новый
  `src/account/capabilities.ts`, `src/ui/roles.tsx`, места, где сейчас решается «показывать ли».
- **Зависимости.** Нет.
- **Риски.** Раздуть профиль полями, которые пока никто не читает. Правило: поле появляется вместе с тем,
  кто его читает.
- **Миграции.** Новые поля необязательные — `PACK_FORMAT` не поднимается.
- **Тесты.** Юнит-тесты `capabilitiesOf` на каждую строку таблицы профилей (`ROADMAP_ARCHITECTURE.md` §5);
  RTL: без входа не видно ИИ через сервер, со своим ключом видно; не-админ не видит админских разделов.
- **Откат.** Одним PR: права — только показ, сервер их пока не проверяет.
- **Параллельно.** Да, со всей линией Айдена.

Задачи:
1. Тип `Capability` и функция `capabilitiesOf(input)` в `src/account/capabilities.ts` + юнит-тесты.
2. Поля профиля в `Organization` (`training?`, `quickActions?` — только те, у которых есть читатель) +
   импорт из `data/<server>/` + тест пакета.
3. Хук `useCapabilities()` в `src/ui/roles.tsx`; перевести на него существующие проверки (админ, лидер).
4. Обновить `ROADMAP_ARCHITECTURE.md` §5 и `docs/ARCHITECTURE.md`.

#### 1Б. Версия пакета и отпечатки статей (P0)

- **Зачем.** Снимок базы для «Дел» и ключ для кэша ответов ИИ. Понятная игроку версия в «Законы и обновления».
- **Что меняется.** Версия для людей («2026.10.1» — день сборки пакета по Москве) и отпечаток каждой статьи
  (FNV-1a) **вычисляются из пакета на лету**, а не пишутся импортом: пакеты не растут (в Тверском 3266 статей),
  импорт и `PACK_FORMAT` не меняются. `version` и `built` остаются; два пакета одного дня различает `built`.
- **Модули.** `src/core/snapshot.ts` (`packLabel`, `articleFingerprint`, `snapshotOf`, `changedSince`), настройки
  «Законы».
- **Зависимости.** Нет.
- **Риски.** Совпадение 32-битных отпечатков у разных текстов — тест проверяет весь пакет Тверского.
- **Миграции.** Нет: в пакете ничего нового.
- **Тесты.** Отпечаток меняется только при изменении текста статьи; тест «пакет не устарел» проходит.
- **Откат.** Поля просто перестают писаться.
- **Параллельно.** Да.

Задачи: 1) `packLabel` и строка в настройках; 2) отпечатки и снимок + тесты; 3) docs.

#### 1В. Понятный ответ «не найдено» (P2, функция для игроков)

- **Зачем.** Сейчас три разных «Ничего не найдено» (главный поиск, меню документов, быстрый поиск), и ни одно
  не говорит, что искали. Игрок не понимает, переформулировать или искать не там.
- **Что меняется.** `core` отдаёт объяснение пустого результата: сколько документов и каких видов проверено,
  какие слова искались после нормализации, похожие слова из индекса и словаря, номер статьи, если запрос похож
  на номер. Один компонент `NoResults` во всех трёх местах. Никаких подсказок из ИИ.
- **Модули.** `src/core/search.ts`, `src/core/wordIndex.ts`, новый `src/ui/NoResults.tsx`, `Overlay.tsx`,
  `DocumentsMenu.tsx`, `QuickSearch.tsx`.
- **Зависимости.** Нет.
- **Риски.** Шум в быстром поиске поверх игры — там компактный вариант в одну-две строки.
- **Тесты.** Юнит: объяснение для пустого запроса, опечатки, номера; RTL в трёх местах. Сверка с макетом C.
- **Откат.** Вернуть старую строку.

Задачи: 1) `explainEmpty(query, pack)` в core + тесты; 2) `NoResults` + главный поиск; 3) меню документов и
быстрый поиск (компактно); 4) «Что нового».

### Этап 2 — Overlay без монолита, словарь, команды · skyze

**Релиз:** архитектура 2А, функции 2Б + 2В (можно двумя релизами).

#### 2А. Состояние из `Overlay.tsx` в хуки (P0)

- **Зачем.** 1691 строка в одном компоненте. «Дела» и команды иначе лягут туда же.
- **Что меняется.** Без изменения поведения: калькулятор (`useCharges`), закрепления (`usePins`), связь с
  быстрым поиском (`useQuickBridge`), недавние и избранное — в свои хуки рядом с `Overlay.tsx`.
- **Риски.** Регрессия. Защита — полный набор RTL-тестов, по одному хуку на PR.
- **Тесты.** Существующие проходят без правок; новые — юнит на каждый хук.
- **Откат.** Каждый PR откатывается отдельно.
- **Параллельно.** Да, но не одновременно с другими правками `Overlay.tsx`.

Задачи: по одному хуку на PR, в порядке: закрепления → калькулятор → быстрый поиск → недавние и избранное.

#### 2Б. Словарь запросов с намерениями (P1) — нужен ADR 0004

- **Зачем.** Меньше обращений к ИИ: «что ему впаяют» → наказание, «чела приняли» → задержание, «по серверу
  можно?» → правила сервера, «что мне положено» → права. Намерение сужает область поиска.
- **Что меняется.** `pack.synonyms` развивается в словарь: слово → формулировки + намерение → виды документов.
  Цепочка: нормализация → словарь → намерение → область → обычный поиск.
- **Модули.** `src/core/search.ts`, `src/core/model.ts`, `src/importer`, `data/<server>/`.
- **Зависимости.** 1В (подсказки «не найдено» берут слова из словаря).
- **Риски.** Намерение сужает поиск слишком сильно — всегда показывать «искать везде».
- **Миграции.** Новая форма словаря — поднять `PACK_FORMAT`, если старое приложение прочтёт её неверно.
- **Тесты.** Набор «запрос → намерение → первая статья» по каждому серверу.

#### 2В. Команды в быстром поиске (P2)

- **Зачем.** Ctrl+K в рамках макета C: «открыть избранное», «последний разбор», «очистить калькулятор»,
  «открыть правила», «статья 65».
- **Что меняется.** Быстрый поиск узнаёт команды и показывает их первой строкой; команда выполняется, только
  если право есть (`capabilitiesOf`).
- **Зависимости.** 1А (права), 2А (хуки).
- **Тесты.** RTL: команда без права не выполняется и не показывается.

### Этап 3 — новая архитектура ИИ · AidenArokij (идёт сейчас)

Как ИИ рассуждает и отвечает — решает Айден; roadmap фиксирует только, что от неё ждут остальные этапы:

- **Кэш проверенных ответов**: ключ — нормализованный запрос + сервер + область + версии источников (1Б);
  изменился источник — ответ не выдаётся как актуальный.
- Нужны ADR Айдена: архитектура ИИ (0006), кэш (0007).

## Definition of Done (для каждой задачи)

- **Код** — в зоне своего владельца; одна задача — один PR в `dev`.
- **Тесты** — сначала тест: RTL через `src/test/renderApp.tsx` или юнит рядом с модулем. Для ИИ — фейковый ИИ
  (`src/test/fakeAi.ts`).
- **Типы** — `npm run typecheck`.
- **Сборка** — `npm run build`; для нативного — `cargo check` в `src-tauri`.
- **Экран** — посмотреть в превью и рядом с макетом C.
- **Документация** — `docs/ARCHITECTURE.md` при смене слоёв; `PRIVACY.md` и README при новых данных;
  «Что нового» в `CHANGELOG.md` для заметного игроку; этот roadmap — статус этапа.
- **Регрессия** — весь `npm test` зелёный, CI зелёный. Сказать прямо, что проверено, а что нет.
