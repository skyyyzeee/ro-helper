# Итоговый отчёт: «ИИ как закрытый слой» (пункт 50 задания)

PR в `dev`, вливать по порядку: #24 → #25 → #27 → #28 → #29 → #30 → #31. (#26 — макет, закрыть.)

**1. Какие AI-функции объединены.**
- «Требования адвоката» и «Разбор задержания» стали одной вкладкой **«Проверка»**: что проверять, выбирается внутри.
- «Составить документ» перестал быть вкладкой: это действие под ответом, а ситуация и факты подставляются из разбора. Кнопка есть и в пустом чате.
- «История» переехала из пункта колонки в панель внутри чата.
- Переключатели «Быстрый / Полный» заменены кнопкой «Подробнее».
- «Авто / Законы / Правила» стал выбором внутри поля ввода.
- Четыре кнопки точки зрения сведены к сторонам, доступным профилю.

**2. Что переименовано.**
- «Разбор ситуации» → «Разбор».
- «Тренажёр» → «Практика».
- «Новый разбор» → «Новый чат».
- «Новые требования» → «Новая проверка».
- «Разбор задержания» → «Ход задержания» (внутри «Проверки»).

**3. Гражданский профиль (без организации).** Разбор (законы и правила сервера), документы гражданина (заявление, жалоба, иск), история, оценки ответов. Вкладок нет — один чат.

**4. Профиль «Крайм».** То же, что у гражданского.

**5. Государственные организации.**
- Всё то же.
- Плюс **Проверка** (`ai.check`).
- Плюс **Практика** (`ai.practice`).
- Плюс служебные документы — рапорт и протокол задержания (`ai.official_documents`).
- Админ (любой профиль) дополнительно видит режим отладки (`ai.debug`) и отзывы.

**6. Что скрыто без capability.**
- Вкладки Проверка и Практика скрыты, а их режимы отказываются работать ещё до вызова ИИ.
- Рапорт и протокол скрыты, при смене профиля выбранный документ сбрасывается.
- Стороны «сотрудник» и «крайм» недоступны чужим профилям.
- Отладка видна только админу.
- Всё задаётся в одном месте: `aiCapabilitiesOf` (docs/AI_ACCESS.md).

**7. Как определяется тип вопроса.**
- `classify.ts` работает без ИИ, по словам закона и правил, синонимам сервера, списку «не об игре», признакам бессмыслицы и номерам статей. Приветствие, погоду, реальные законы РФ, бессмыслицу и номер статьи отвечает само приложение — это 0 вызовов ИИ.
- Утверждённые выражения игроков (словарь) решают то, что слова не решили.
- Если вопрос всё ещё неясен, первый вызов ИИ одновременно даёт поисковые слова и тип вопроса. Без слов правил вопрос идёт к законам, а рядом с ответом показывается подсказка переключиться на правила.

**8. Как ИИ не выходит за пределы базы.**
- Источники берутся только из поиска по базе сервера.
- Единые правила `coreRules`: ИИ не источник закона.
- Ответ строится в JSON, где у каждого утверждения есть id источников.
- Валидатор без ИИ проверяет, что норма есть, что её передали ИИ, что совпадают номер, часть, тип и область, что цифры есть в собственных источниках утверждения и что названные статьи действительно среди источников.
- Наказание считает калькулятор.
- Любой сбой даёт статус «Требует проверки», а не «Подтверждено».
- Текст игрока отделён как данные (защита от prompt injection).

**9. Как отделяются законы от правил сервера.**
- У источника есть тип (S — закон, C — устав, R — правило, O — прочее), он берётся из документа, а не от модели.
- Область поиска сужает базу ещё до поиска: источник другого типа ИИ просто не получит.
- Утверждение не может опираться одновременно на закон и на правило.
- В ответе «По закону» и «По правилам сервера» показаны отдельно, с бейджами.

**10. Как собираются запросы.** Только по нажатию 👍 / 👎 / «Исправить». На сервер ИИ уходят вопрос, статьи, статус и область ответа, тип вопроса, сервер, версия и поправка. Хранятся без номера компьютера, ника, аккаунта и адреса (`feedback.jsonl`). Лимит — 30 в день. Всё описано в PRIVACY.md.

**11. Как из feedback появляются QueryAlias / QueryExample.** Админ в программе: Отзывы об ИИ → «Утвердить» с нормальной формой, то есть выражение, слова закона, область, вопрос, правильные статьи (`reviews.json`). Дальше:
- выражение с нормальной формой попадает в словарь `/v1/aliases`, по которому поиск понимает игроков без ИИ;
- вопрос со статьями становится примером экзамена (`/v1/examples`, `npm run eval -- --approved`).

Отклонённые и отложенные на перепроверку не используются. Само по себе ничего не меняется (docs/AI_DATASET.md).

**12. Какие eval-тесты появились.** К 45 ситуациям по законам добавлено 28 ловушек по категориям: SERVER_RULE, MIXED, NONSENSE, OUT_OF_SCOPE, AMBIGUOUS, HALLUCINATION_TRAP, WRONG_NUMBER_TRAP, CROSS_SERVER, FALSE_CLAIM, PROMPT_INJECTION, FOLLOW_UP. К ним добавляется APPROVED — утверждённые админом примеры. Проверки прав (ROLE_RESTRICTED) — в автотестах vitest.

**13. Какие hard gates.**
- Подтверждённая галлюцинация, то есть «Подтверждено», но без опоры в источниках.
- Применение запрещённой статьи («777», нумерация чужого сервера).
- Вызов ИИ там, где ответ давало приложение.

Те же ловушки с «нарочно плохим» поддельным ИИ стоят в vitest и прогоняются на каждом PR (`grounding.test.ts`).

**14. Как считается hallucination rate.** `CONFIRMED_HALLUCINATION_RATE` — доля разборов со статусом «Подтверждено», в которых отдельная проверка (`confirmedHallucinations`) находит норму не из источников, утверждение без источника, цифру не из его источников или упомянутую статью не из источников. На GigaChat-2: 0% (0 из 64).

**15. Как работает regression suite.**
- `npm run eval -- --save-baseline` сохраняет базовую линию.
- Следующий прогон сравнивается с ней по категориям «новые провалы / исправлено / регрессии по жёстким воротам / без изменений».
- Любые сработавшие жёсткие ворота дают код выхода 1.
- С `--approved` в проверку входят и утверждённые примеры.

**16. Какие существующие тесты прошли.**
- `npm test` — 533 из 533. Один старый тест поиска поверх игры иногда падает по времени под нагрузкой и проходит отдельно.
- `npm run test:server` — 8 из 8.
- typecheck и `npm run build` проходят.
- Живой экзамен GigaChat-2: 54 из 73, ворота 0, галлюцинации 0%. Прогон был до словаря: словарь пока пуст, отзывов ещё нет, и на экзамен он не влияет.

**17. Что осталось нерешённым.**
- Проверки прав на сервере ИИ нет — по решению 1а: организацию выбирает сам игрок, и сервер проверял бы то, что ему сообщает приложение. Переход на подтверждённое членство описан в docs/AI_ACCESS.md.
- Сервер ИИ нужно обновить после слияния в main (`install.sh`) и создать ключ админа (`set-key.sh admin`). До этого отзывы, словарь и админка отзывов не работают.
- Первый вызов ИИ (поисковые слова) пропускается только при совпадении со словарём. Общего порога уверенности поиска нет: он снижал бы точность.
- В отладке нет сырого текста запроса и ответа ИИ, только классификация, область, слова, источники, проверки и вызовы.
- В наборе данных хранятся выражение, нормальная форма, область, вопрос и правильные статьи. Сущности и факты целиком не хранятся ради приватности.
- Точность: 54 из 73. Оставшиеся промахи — в основном выбор модели между похожими статьями и редкие формулировки. Их будут закрывать отзывы, словарь и синонимы.
